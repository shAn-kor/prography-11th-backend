# ADR-004: 크로스 도메인 실패 처리

- Status: Proposed
- Date: 2026-02-26

## Context
회원 등록, 출석 체크, 출결 수정은 다중 도메인 변경이 동반되어 부분 실패 시 정합성 문제가 발생한다.

## Decision
- 1순위: 가능하면 하나의 Application Service 트랜잭션으로 처리한다.
- 2순위: 기술적 제약이 있으면 Facade에서 보상 로직을 구현한다.
- 보상 로직이 필요한 경우, 실패 시나리오와 역연산을 테스트 케이스로 명시한다.

## Alternatives Considered
- 항상 보상 로직: 구현 복잡도와 실패 케이스 누락 위험이 증가한다.
- 항상 분산 처리: 정합성 보장이 어렵다.

## Consequences
- 장점: 핵심 흐름의 데이터 일관성 보장 수준이 올라간다.
- 단점: 일부 흐름에서 설계/테스트 난이도가 증가한다.
