# ADR-008: 출석 체크 검증 순서 계약

- Status: Proposed
- Date: 2026-02-26

## Context
출석 체크는 다단계 검증이 포함되며, 순서가 바뀌면 반환 에러와 사용자 경험이 달라진다.

## Decision
아래 검증 순서를 계약으로 고정한다.
1. QR 유효성
2. QR 만료
3. 세션 진행 상태
4. 회원 존재
5. 회원 탈퇴 상태
6. 중복 출결
7. 기수 소속 정보

## Alternatives Considered
- 성능 기준 재정렬: 에러 우선순위 계약과 충돌 가능성이 있다.
- 병렬 검증: 구현 복잡도 증가 및 에러 결정 규칙 모호화.

## Consequences
- 장점: 실패 응답이 예측 가능하고 테스트가 명확해진다.
- 단점: 요구 변경 시 영향 범위가 넓다.
